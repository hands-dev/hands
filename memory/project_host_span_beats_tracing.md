Enrich the chat-turn distributed trace (ENG-1388) so the fleet-host **course lifecycle** shows as distinct Gantt rows: the 5 beats `exchange → prepare_checkout → engine_setup → work(ttft·generation) → detach`. Goal: de-conflate infra latency (hydrate/USER.md regen/engine boot) from model latency — today all of it hides inside `host.ttft`, and `detach` is invisible.

**Decided design (2026-07-30): per-turn enriched.**
- Wire: host reports `timings.executionBeats: [{name,startMs,endMs}]` as **absolute epoch-ms** windows (host owns the wall clock after claim). Chosen over claim-anchored offsets specifically so future drill-down INTO the work beat (tool calls / model phases) nests with no anchoring math.
- API rendering: host-reported beats **supersede** the claim-anchored ttft/generation derivation (gives a TRUE ttft from engine-launch); `host.queue_wait` stays server-derived (host never sees `created`). Warm turn / un-reprovisioned host → no beats → falls back to `computeHostSpanWindows` unchanged. Fully back-compat.
- Cold checkout shows all beats; a warm subsequent turn (same held checkout) shows just queue_wait/ttft/generation — the shape difference is a feature (you can see warm hits skipping the infra beats). `detach` is post-`/response`, so deferred to a completion-path report (allow-listed already).
