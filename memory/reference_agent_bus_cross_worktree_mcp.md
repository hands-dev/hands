Michael has a personal, machine-local MCP server **agent-bus** for cross-worktree/pane Claude Code
messaging (built 2026-07-30 from INN-239, but deliberately NOT committed to the ampersand repo — it's
his personal tool).

- **Location:** `~/.claude/tools/agent-bus/` (self-contained, own `node_modules`, `node:sqlite` + `@modelcontextprotocol/sdk` + `tsx`). Standalone `npm` project, not a monorepo package.
- **Registered:** user-scoped (`claude mcp add agent-bus -s user -- <tsx> <src/server.ts>`), so it's available in every project/worktree. Remove/re-check via `claude mcp remove|get agent-bus -s user`.
- **Shared state:** SQLite DB at `~/.claude/coordination/agent-bus.db` (WAL); one stdio process per Claude instance, no daemon.
- **Tools:** `agent_bus_send` (`to` = agent id or `"*"`), `agent_bus_receive` (long-poll), `agent_bus_peers`, `agent_bus_history`, `agent_bus_board` (standup snapshot).
- **Agent id** derived from cwd: `AGENT_BUS_ID` env → `--agent-id` → `wt<n>` from `…worktree-n` basename → basename. This worktree (ampersand-worktree-4) registers as `wt4`.
- **Passive standup (Phase 1, shipped 2026-07-30):** two GLOBAL hooks in `~/.claude/settings.json` call the CLI mode — `Stop` → `node dist/server.js publish` (async; status from git branch + heartbeat + auto-journal new commits & memory-store writes) and `UserPromptSubmit` → `node dist/server.js board` (injects a quiet DELTA of peer activity/learnings/collisions each prompt). Delta-based: first read per pane baselines silently. Claude Code picks up new `~/.claude/settings.json` hooks in ALREADY-RUNNING sessions — no restart needed (observed 2026-07-30). Presence bands: active <3m · idle 3–15m · offline >15m (heartbeat only at turn-end, so windows are generous).
- **Dashboard:** `cd ~/.claude/tools/agent-bus && npm run dashboard` → http://127.0.0.1:4319 (`node dist/server.js serve`; port via `AGENT_BUS_PORT`). Read-only localhost `node:http` server (does NOT register as an agent). Fixed 3×2 numbered grid (WT 1‑2‑3 / 4‑5‑6, big number per cell; non-numbered agents in an "other" strip), status dot (active/idle/offline), per-cell commits/learnings/messages. Top **conductor lane** = priorities · needs-you · in-flight · recent decisions. Polls `/api/state` 2s.
- **Foreman (command center):** the MAIN checkout `/Development/ampersand` registers as agent `foreman` (special-cased in resolveAgentId; override `AGENT_BUS_FOREMAN_BASENAME`). Worktrees escalate open decisions via `agent_bus_ask`; foreman triages vs Michael's ranked daily priorities — auto-resolves only a small safe slice (reversible · on-priority · scoped-to-asker · high-confidence), else escalates to Michael with a rec + macOS ping. Run in main pane via `/loop /foreman` (skill `~/.claude/skills/foreman/SKILL.md`). Priorities file: `~/.claude/coordination/priorities.md` (editable; foreman asks if unset, re-confirms when stale). Tools: `agent_bus_ask|questions|answer|escalate|priorities`. Questions lifecycle: open→needs_human/answered. Answers route back to asker via board delta.
- **Foreman = ORCHESTRATOR, delegates ALL real work — never plans/codes itself.** Drives each priority forward by delegating the next step to an available worktree (usually "make an end-to-end plan" first) via `agent_bus_send`, reviews what comes back, decides refine/ticketize(`/linear`)/build — always by re-delegating. Also: **review/merge gatekeeper** (picks `/code-review` depth low/default/high by complexity itself; recommends-but-ALWAYS-escalates admin-merge — never force-merges) and **GitHub team-awareness** `agent-bus gh-poll` (via `gh`; records other engineers' open+merged PRs → dashboard "team · github" lane; relevant-by-file/ticket PRs flagged `↔ wtN` + propagated). Delegation is a TRACKED lifecycle: `agent_bus_delegate({to,title,body,priority})` → task `assigned`→`in_progress`→`returned`(+result)→`done`; tools `agent_bus_delegate|tasks|task_update`; board surfaces assigned-to-worker + returned-to-foreman deltas; dashboard "delegations" lane shows the lifecycle. Workers do delegated plans/investigations/builds fully in-worktree (reversible, own branch) via `task_update in_progress→returned`. Foreman skill `~/.claude/skills/foreman/SKILL.md`, worker `~/.claude/skills/worker/SKILL.md`.
- **Build gotcha:** MCP server runs `src/` via tsx; HOOKS + dashboard run compiled `dist/` under node (speed). After editing `src/`, run `npm run build` or they run stale code.
- **Design/roadmap:** `~/.claude/tools/agent-bus/DESIGN.md`. Phase 2 (not built) = delegation/workers: task lifecycle (`dispatch`/`claim`/`complete`) + a low-frequency idle-gated dispatcher loop auto-armed by a `SessionStart` hook, so "have an available WT dig into this" works. Watch-items: injection token cost; self-arm reliability.
- **Workers (autonomous responders):** run `/loop /worker` in a pane → it long-polls `agent_bus_receive({wait_seconds:15})` each pass (model parks cheaply, returns the INSTANT a message lands — measured ~150ms turnaround; 15s is just the re-arm ceiling), replies/escalates/does safe in-worktree work, yields. Skill `~/.claude/skills/worker/SKILL.md`. Dedicate a pane to it; keep working in others. Main pane runs `/loop /foreman` instead.
- **Awareness vs handling decoupled:** board (UserPromptSubmit) SHOWS incoming direct messages by time-window (`messagesForSince`, never consumes) for passive awareness; a worker HANDLES them via the receive cursor (`messagesSince`/`agent_bus_receive`). So glancing at a message doesn't mark it done, and a worker draining doesn't steal it from your view.
- **Limits:** MCP can't wake an idle pane — a worker's `/loop` self-wake is the driver; per-send `~/.claude/coordination/<agent>.notify` file for a `tail -f`/Monitor nudge. Plaintext in a local 0600 DB — no secrets in bodies.
