**Decision 2026-07-03 (Option B): venue selection becomes skill-owned.** Root-caused why &michael's first-visit coffee shop (The Brew, Gladstone OR) never surfaced. The photo GPS DID land + resolve (`rsig_dAVas`, `spots_clustered=2`, **`venues_resolved=2`** — NOT 0; an earlier note misread it), but the morning spot resolved to a **nail salon (Seaora, 18m) instead of The Brew (coffee_shop, 20m)**. Cause: `resolveSpotsToVenues` calls `nearby(lat,lng, limit=3, VENUE_IDENTITY_TYPES)` and takes the **nearest-within-100m by raw distance**. In a dense block 3 personal-care venues at 18–19m crowd out the coffee shop at 20m (2m = pure GPS noise); `limit=3` truncates The Brew (4th) before ranking. All candidates were OPERATIONAL, so "active" wasn't the discriminator — the ignored signals are andee venue-type affinity, the photo's MLKit labels, and prominence (The Brew 78 ratings vs salon 14).

**Chosen path = Option B (over A).** Drop Google's `includedTypes` type pre-filter entirely (also kills the 50-type cap — the list is a frozen 50 at Google's max today). `nearby()` returns N nearest of ALL types = pure geometry; the **enrichment skill picks** the identity-right venue per spot (affinity + photo labels + prominence + distance as a coarse bucket). `VENUE_IDENTITY_TYPES` may survive only as a broad "exploration floor" (never draft a gas station as identity), not the hard pre-filter. `resolveSpotsToVenues` stops doing mechanical nearest-match → fetch candidates → hand to skill → persist pick. B over A because A (per-andee 50-type subset sent to Google) narrows recall + is self-reinforcing/echo-chamber. Keep a broad floor so discovery of new facets survives. NOTE: even a correct pick draws NO andee-facing card today (ENG-1115 — photo+dwell rails write substrate only, feeding the enrichment reasoner); surfacing a first-visit venue card is a separate product call.
