**INN-187 REFINED SCOPE + architecture proposal doc (2026-07-23).** Deliverable was NOT code — it's a **Notion architecture proposal for engineer review**: https://app.notion.com/p/3a651f455bba8111bc67dafb93dbaf45 (Engineering "Brainstorm Session" DB `data_source_id 1fe51f45-5bba-8028-b00d-000bbb32a673`; linked on INN-187). Refined scope (Michael's call): #187 is **write-only + purely additive** — define the task CONTRACT + store tasks that **accumulate unclaimed**; **claim/lease/assignment deferred to #2/#3**; **nothing deprecated/replaced** (dormant `heavy_work_orders` = design template left in place; live `runtime_channel_messages` untouched — only an additive guarded interactive producer beside its existing NOTIFY). `tasks` = **THIN dispatch ledger, not content** (new table, NOT generalizing heavy-work in place); inline lease/epoch like runtime_channel_messages; active-partial dedupe unique on `(dedupe_key)`. **Task schema heavily trimmed in review (Michael):** columns = `id, type, status, target_andee_id?, target_host_id?, session_id?, directive_ref?, min_image_version?, dedupe_key, epoch/lease inline, terminal_*, timestamps`. **`type`** (open TEXT, not enum: chat_bridge/location_enrichment/loop_advance/photo_enrichment/fleet_upgrade) is the intrinsic field; only `task_status` is a pgEnum. **DROPPED** (all per Michael): `lane`+`priority`+`absolute_deadline_at` → orchestrator SCHEDULING derives from `type` (not on task); `resource_class` → no need; `objective`/`context_refs`/`params` → live in a **directive** elsewhere, task only holds `directive_ref` pointer (chat_bridge needs none). **Eligibility = ORCHESTRATOR-owned, capability rides the HEARTBEAT (FINAL, Uber-dispatch model, Michael):** dispatch matches task requirements (from `type`) against each host's **last-heartbeat capability set** and offers a task only to **capable + available** hosts; the driver/host just **accepts or declines** (not "am I capable"). **Capability source = the IMAGE self-reports `{status, version, capabilities}` on its heartbeat** — the image is the single source of truth; **NO central version→caps map** (that idea was considered then dropped). Orchestrator's "inventory" = the last heartbeat it already receives → drift ≈ one interval. **Upgrade = heartbeat state transitions**: `online(vN)` → **`unavailable` while upgrading (excluded from dispatch)** → `online(vN+1, new caps)` (self-healing; never offered work it can't do). Report ≠ self-select → stays orchestrator-owned + pull-based/NAT-safe; host accept/decline **veto** = final backstop. Reuses existing `agent_runtimes` heartbeat statuses (`provisioning/online/degraded/offline/failed`) + `runtime_pool_slots.draining` + version digests; **INN-185 extends the heartbeat payload with the capability set**. Consequence: **`min_image_version` DROPPED from the task** (eligibility not self-declared).

**Dispatch = ASSIGN-TO-ONE + WATCH (FINAL, Michael):** two phases. **(1) Assignment** — the orchestrator (matchmaker) scans unassigned tasks (`target_host_id IS NULL`), picks ONE capable+available host from heartbeats, and **writes `target_host_id = H`**; that DB write IS the assignment (eligibility decided here, once; enables forced placement). **(2) The watch** — each runner long-polls/LISTENs ONLY its own queue (`tasks WHERE target_host_id = self AND status='queued'`) and picks up immediately; NO eligibility check at pickup. **Once assigned to a specific runner the orchestrator has no job** — the agent takes it because it's in its queue. **Pre-pinned tasks (fleet-ops) skip assignment** (already in that runner's queue). Failover: decline/lease-lapse → orchestrator **reassigns** (repins). Tradeoff vs race-to-claim/SKIP-LOCKED: assign-to-one is deterministic + enables forced placement but **failover isn't automatic** → the reassign loop must be prompt; interactive matchmaker must fire on-enqueue against a warm pool (INN-189). Indexes reflect this: `tasks_watch_idx (target_host_id, status, created_at)` + `tasks_assign_idx (status, type, created_at) WHERE target_host_id IS NULL`. Slack #dev-team-actual posted with the summary + Notion link.
