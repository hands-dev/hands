`apps/mobile/ios/` and `apps/mobile/android/` are git-ignored (see `apps/mobile/.gitignore` lines 7-8). They are **prebuild outputs**, not hand-maintained sources. EAS regenerates them from `app.config.ts` on every build, and locally they're regenerated by `npx expo prebuild`.

**Why:** Means `app.config.ts` plugin blocks (e.g. `expo-location` → `locationWhenInUsePermission`, `expo-contacts` → `contactsPermission`) ARE the authoritative source of every `NS*UsageDescription` / Android permission. Manual edits to the local `ios/AndLocal/Info.plist` or `android/app/src/main/AndroidManifest.xml` are **local-only and get wiped by the next prebuild**. Do not commit them as a workaround — they aren't tracked anyway.

**Symptom when missed:** After editing `app.config.ts` and reloading the JS bundle without prebuilding + rebuilding the dev client, the local Info.plist still lacks the new `NS*UsageDescription`. iOS hard-crashes the app the instant the matching `*PermissionsAsync()` call fires. No JS error in Metro — the native runtime kills the process. Easy to misdiagnose as a JS bug. EAS builds (preview/production) are unaffected because EAS prebuilds in CI.

**How to apply:**
1. Add or change the plugin block in `apps/mobile/app.config.ts`.
2. From `apps/mobile/`: `npx expo prebuild --clean` to regenerate the local `ios/` + `android/` from the updated config.
3. iOS: `cd ios && pod install`, then rebuild via Xcode or `pnpm exec expo run:ios`.
4. Android: rebuild via `pnpm exec expo run:android` (Gradle picks up the new permission automatically).
5. JS reload alone does NOT pick up native config changes.

**Earlier (now-superseded) belief:** A prior version of this note claimed `ios/` was committed and prebuild was avoided to preserve manual native modifications. That's not the current setup — both native dirs are git-ignored, EAS prebuilds, and `app.config.ts` is the single source of truth.
