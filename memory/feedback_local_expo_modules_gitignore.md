`apps/mobile/.gitignore` has `ios/` and `android/` on bare lines (intended for the top-level prebuild output dirs). Those patterns ALSO match any `ios/` / `android/` directory anywhere under `apps/mobile/`, including under a local Expo Module at `apps/mobile/modules/<name>/ios/`.

**Symptom:** `git add apps/mobile/modules/<name>` reports success and the commit looks normal, but only the JS files (`index.ts`, `package.json`, `expo-module.config.json`) land. The Swift / ObjC / podspec files under `modules/<name>/ios/` are silently ignored. The PR pushes, CI passes typecheck (TS only sees the JS surface via `requireOptionalNativeModule`), and the iOS build at `expo run:ios` time fails because the native source isn't in the checkout.

**Fix:** add negation patterns AFTER the broad excludes:

```
# Native builds (generated by expo prebuild)
ios/
android/
# Local Expo Modules ship their own native source in modules/*/{ios,android}.
# Those ARE tracked — only the top-level prebuild output dirs are ignored.
!modules/*/ios/
!modules/*/android/
!modules/*/ios/**
!modules/*/android/**
```

Both `modules/*/ios/` AND `modules/*/ios/**` are needed: the directory pattern un-ignores the dir itself, the `**` pattern un-ignores its contents. Verify after editing with:

```
git check-ignore -v apps/mobile/modules/<name>/ios/<File>.swift
```

The output should reference the `!modules/*/ios/**` line, NOT the bare `ios/` line.

**Discovered:** ENG-845 PR (visit-based dwell detection). First push of the PR was missing the entire native iOS implementation; only the JS bindings landed. Caught when reviewing `git show --stat HEAD` and seeing zero `.swift` / `.m` files. Force-pushed an amended commit with the gitignore fix + the previously-missing native source.
